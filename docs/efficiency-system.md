# 效率系统｜AI、Lua、命令行

## 上层原则

先把一次性劳动拆成可重复流程，再考虑自动化：

1. **标准化**：写清输入、输出、状态、异常和验收标准；
2. **最小跑通**：先用一条命令、一个样本或一个脚本跑通；
3. **日志验收**：以服务器日志、到账结果和实际状态为准，不以“请求发出”代替成功；
4. **批量扩量**：跑通后再扩样本、扩关卡、扩配置；
5. **工具化沉淀**：把重复步骤做成脚本、检查表或 Skill，保留回滚和复现路径。

这套顺序适用于数值模拟、活动配置、奖励验证和 AI 原型制作。核心不是“用了多少工具”，而是把不可控的手工操作变成可检查、可复现、可回滚的流程。

## Lua、GM 与命令行

数值和系统测试经常卡在“等程序改数据”。我的做法是把测试路径拆成自己能操作的几步：

- 用 GM / 命令行改资源、服务器时间、任务状态、功能解锁和活动开关；
- 用 Lua 批量发奖、推进任务、循环构造样本，避免手点；
- 脚本按 ID 做重复保护，失败先查日志，不整批重发；
- 测试前记录初始状态，测试后按日志核对奖励到账、掉落 ID 和任务状态；
- 发奖、重置、提交等有副作用操作单独确认，不在未验证时批量执行。

## AI 提效流程

1. **先读现有内容**：读工程、接口、GM 命令格式、配置字段和已有文档，不凭记忆编接口。
2. **写清目标和边界**：明确要解决什么问题、输入是什么、输出是什么、什么算验收通过。
3. **生成最小版本**：先让 AI 写一个能跑通的最小脚本、表格、模拟或 HTML 原型。
4. **人工检查**：检查字段、状态、边界、异常和是否有不可逆操作。
5. **跑一条样本**：先单条运行，查看返回值、日志和实际结果。
6. **批量扩量**：单条通过后再扩关卡、扩样本、扩配置。
7. **沉淀与回滚**：通过 Git / Fork 或版本记录保留可追溯版本，失败可回退。

## 我在哪些环节用 AI

- **数值模拟**：用 Codex 搭可调参数的战斗原型，批量跑战斗时长、胜率、剩余血量和技能释放次数；
- **表格与公式**：辅助写 Excel 公式、批量拉表和字段检查；
- **Lua / 测试脚本**：在读懂 GM 模块和参数格式后生成最小脚本，再由自己执行和验收；
- **HTML 原型**：把系统规则做成可点击原型，先验证主操作链和状态反馈；
- **工程管理**：用 Git / Fork 管理 AI 生成代码，按分支拉取、提交和回滚；
- **文档与复盘**：把对话、设计判断和验证结果整理成可检索的材料。

## AI 的边界

AI 负责生成、批量、查漏和加速，不负责替我做目标和取舍。目标、创意、商业判断和验收标准仍然由人负责。涉及发奖、重置、提交、删除和线上变更时，先确认、再执行；服务器日志和实际结果才是最终证据。
