# 产品判断｜像制作人一样汇报

## 1. 不因为竞品有就做

立项先回答四个问题：

1. 市场供给是否同质，用户为什么换游戏；
2. 目标用户是谁，他们在什么场景下需要这个玩法；
3. 我们现有能力能否做出差异，而不是只换皮；
4. 上线用什么指标证明成功。

竞品拆解只回答“它为什么有效”，不直接抄 UI 和功能。

## 2. 用项目回答“为什么做”

- 青蛙战斗：不是给换装游戏硬塞战斗，而是验证强数值玩法对现有用户群的接受度，尝试扩大用户覆盖。
- Merge 活动：用现有 Reward / Shop / Popup 控成本，用剧情三选一、棋盘机制和通行证体验做差异。
- 试玩广告：把广告当 30 秒可玩原型，用钩子和“差一点赢”的结构做低成本市场测试。

## 3. 新玩法拆成四层

- 机制：有没有新的玩家决策；
- 节奏：是否服务目标时长和用户习惯；
- 表达：是否能被看见、理解和传播；
- 商业：是否不破坏体验，能形成可持续的投放或付费。

四层都要有可验证指标，不能只看功能有没有做完。

## 4. 向老板汇报的顺序

为什么现在做 → 为什么是我们 → 为什么不抄 → 投入和风险多大 → 怎么验证 → 失败怎么退。

功能、配置和排期放在后面。方向错了，做得再快也是浪费。

## 5. 执行与复盘

AI 用来扩方案、批量拉表、写测试脚本和查漏；创意、取舍和验收由自己判断。

复盘分五层：目标、机制、数值、信息、验证。下一版先改判断标准，再调参数，避免只在小数值上打补丁。


## 6. 市场判断

看市场不能只看榜单有什么，而要拆：

- 品类供给是否同质，用户为什么从旧产品迁移；
- 竞品真正有效的机制、情绪和传播点是什么；
- 我们的团队、内容和工具能不能形成差异；
- 买量、内容传播和回收周期是否支持这个方向；
- 上线用什么指标证明成功，失败时怎么退。

竞品拆解只回答“它为什么有效”，不直接抄 UI 和功能。

## 7. 范围与成本

制作人视角不是把所有想法都做进去，而是先划清：

- 哪些复用现有系统、配置和美术；
- 哪些必须新建，新增成本在哪里；
- 哪些本轮明确不做；
- 最小闭环是什么，什么时候可以开始验证；
- 程序、美术、QA、本地化和服务器依赖怎么排；
- 排期留多少返工缓冲，什么情况下砍范围。

## 8. 团队与交付

- 需求文档写清目标、状态、字段、异常、验收人和边界；
- 配置表检查字段、ID、引用、奖励映射和前后端字段边界；
- UI、Icon、动效、Localization、Popup 和 QA 需求前置；
- 程序实现、服务器验证、补单和回滚方案一起设计；
- 每个风险有 owner、触发条件和处理方案。

## 9. 商业与运营

- 活动货币、商店、抽卡、首杀/复刷要和体验一致；
- 奖励既要支撑过程反馈，也要能收口；
- 投放侧看 CTR / CVR / CPM / ROAS，不只看创意好不好看；
- 活动周期、限购和产出节奏要服务留存与回收；
- 不把短期付费峰值当成长期成功。

## 10. 上线与复盘

- 上线前约定核心指标、观察窗口、停止条件和回滚方案；
- 先小流量验证，再扩大投入；
- 复盘分目标、机制、数值、信息、验证五层；
- 下一版先改判断标准和流程，再调参数；
- 把重复问题沉淀成检查表、工具或 Skill。
