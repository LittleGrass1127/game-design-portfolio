# 系统与数值方案｜断线托管 + 风迹手册

这是一份系统 + 数值联合作答，重点不是给出一个“看起来对”的答案，而是把规则、服务端字段、异常、防滥用、预算和验收指标讲清楚。

## 一、系统题：断线托管与重连

### 目标

四人小队中有人断线时，缩短少一人操作的时间；同时不让断线成为自动采集、规避淘汰或逃避排位扣分的手段。

### 规则取舍

- 保留基础托管 AI，只允许移动、避险、靠近队友和普通采集；
- 取消断线后的 20 秒原地等待，对局不暂停；
- 断线角色照常受击、受控、淘汰；
- 重连不重置位置、血量、冷却和背包；
- 每名玩家每局累计回控预算 90 秒，防止反复短断线滥用。

### 服务端字段

连接状态、角色生存状态和控制权分别记录。控制权版本号每次交接递增，拒绝旧客户端和重复交接。累计离线时长和剩余回控预算由服务端维护，重连不清零。

### 状态流转

正常在线 → 疑似断线 → 确认断线 → AI 托管 / 离线观战 → 重连交接 → 永久离开 / 已结算。

疑似断线保留最多 3 秒确认窗口；确认断线后检查参与状态、结算状态、剩余预算和生存状态；已淘汰角色只恢复观战，不再控制角色。

### 防滥用和补偿

- 反复短断线也累计时长；
- 预算耗尽后永久离开本局；
- 已判定生效的攻击、消耗和持续效果照常结算；
- 排位积分、任务进度和奖励补偿按最终结算状态处理；
- 重连只恢复控制权，不重算比赛结果。

### 验收指标

断线恢复率、平均不可控时长、AI 托管时长、预算耗尽率、重连失败率、异常重连投诉、排位结算争议和奖励到账率。

## 二、数值题：七日活动“风迹手册”代币方案

### 现有模型

轻度、中度、重度用户活跃天数分别为 3、5、7 天，占比分别为 45%、40%、15%。现有规则下三类用户总代币为 42、130、322 枚，加权人均 119.2 枚。

### 两个方案

- 方案 A：按局数追加代币。加权人均 138.3 枚，增幅 16.02%，超过 10% 预算；轻度用户只有 48 枚，仍未达到 50 枚第一档。
- 方案 B：活动内达到第 3 个活跃日，一次性获得 8 枚。轻度用户达到 50 枚第一档，加权人均 127.2 枚，增幅 6.71%，低于 10% 预算。

### 选择

选择方案 B。它同时满足“轻度用户达到第一档”和“全体加权人均增幅不超过 10%”两个约束。

### 风险与监控

- 玩家只登录或打一局就离开：监控第 3 活跃日对局完成率、挂机率、单日仅一局占比和第 4 日回访；
- 轻度用户拿完第一档后动力不足：在进度界面明确显示“再完成 1 局可达第一档”；
- 玩家误解“第 3 个活跃日”：写成“活动期间累计完成有效对局的第 3 天”，显示 1/3、2/3、3/3；
- 行为变化导致超投放：按账号随机固定分组，完整观察 7 日周期，按分组初始符合资格账号计算人均，不只看领取者。

### 结论边界

以上是静态模型下的规划测算，不是上线后的真实效果。上线后要用实际活跃天数、局数、领取率和人均投放重新校准。
