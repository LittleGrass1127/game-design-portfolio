# 精灵巡游季 · 逆推策划文档

> 本文从 `prototypes/jingling.html` 的代码逆推整理，数值与文案均以 `config/` 为准。

## 1. 定位与设计问题

系统策划笔试中的四个交互原型之一（同组：六分街深夜剪辑室、春风编花会、旧影回声）。飞书原型合集页对这组原型的定位是：“可离线运行的 HTML 原型，用于验证主操作链、界面信息和规则反馈”；对本原型的描述是“传闻选择、环境判断、共鸣与结伴挑战”。

原型要验证：**把“收服/结伴”从数值门槛改成“读环境 → 选对方式”的判断题后，玩家能否从传闻文本中自己推出答案；选错时反馈是否足够解释原因并允许立即重试。** 页面标题文案直接写明了这一点：“结伴不是数值门槛：错误选择会说明原因，并允许立即重试。”

## 2. 核心操作链

```
选择传闻（地点 + 时间 + 环境）→ 阅读场景描述
   → 选择共鸣方式 → 尝试结伴
       ├ 错：返回该传闻专属提示，可换选项重试（无惩罚）
       └ 对：精灵现身，展开协作挑战
   → 按 观察 → 稳定 → 同步 的顺序点击三步
       ├ 按错：已完成步骤清空，提示正确顺序
       └ 完成：收录图鉴 + 点亮一段公共巡游路线
```

- 切换传闻会重置共鸣、结伴、挑战全部状态。
- 挑战按钮的排列顺序（稳住风铃 / 观察微光 / 同步步伐）与正确顺序不同，玩家需要读挑战说明而不是从左到右点。

## 3. 规则与反馈

| 规则 | 代码位置 | 说明 |
| --- | --- | --- |
| 结伴判定 | `rules.tryPartner` | 所选共鸣 = 传闻的 `correctResonance` 即成功 |
| 失败反馈 | `text.partnerFail` + `rumors.failHint` | 每条传闻一句专属提示，指向场景中的关键环境词 |
| 挑战序列 | `rules.applyChallengeAction` | 期望动作 = 正确序列第 `已完成数` 位；不符则清空 |
| 已完成按钮 | `ui render` | 已完成的步骤按钮禁用并高亮；全部完成后全部禁用 |

传闻与答案（`config/rumors.csv`）：

| 传闻 | 关键环境 | 正确共鸣 | 精灵 |
| --- | --- | --- | --- |
| 雨后桥边有微光 | 风从水面吹向旧街 | 风向铃 | 风铃精灵 |
| 咖啡店窗台轻响 | 桌上的旧糖纸 | 蜜糖纸 | 糖羽精灵 |
| 旧巷会重复脚步声 | 走得越慢回声越清楚 | 放慢脚步 | 回声精灵 |

三种共鸣与三条传闻一一对应，不存在“万能选项”。

## 4. 数值公式（取自代码）

共鸣进度圆环（`flow.score`，圆环角度 = 值 × 3.6°）：

| 状态 | 值 |
| --- | --- |
| 初始 | 12 |
| 已选共鸣 | 38 |
| 已结伴 | 72 |
| 已收录 | 100 |

顶部进度条（`flow.progress`）：

- 初始 15；已选共鸣 38；
- 已结伴：`partneredBase + 已完成步数 × perStep = 60 + n × 13`（n = 0/1/2 时为 60/73/86）；
- 已收录 100。

## 5. 配置表说明

| 文件 | 字段 | 用途 / 改动影响 |
| --- | --- | --- |
| `rumors.csv` | `id, title, hint, name, scene, correctResonance, spirit, failHint` | 左侧传闻按钮（title/hint）、中央场景（name/scene）、答案与精灵名、失败提示。`correctResonance` 必须引用 `resonances.csv` 中的 id |
| `resonances.csv` | `id, name, desc` | 右侧共鸣按钮。增删需同步传闻答案，否则测试中“一一对应”断言失败 |
| `challenge-actions.csv` | `id, label, displayOrder, step` | `displayOrder` 控制按钮排列，`step` 决定正确顺序（1..N 连续）。改 `step` 即改挑战答案；增加行会同时增加挑战步数（进度与文案中的 `{total}` 自动跟随） |
| `flow.json` | `defaultRumor, score.*, progress.*` | 默认选中的传闻；圆环与进度条各阶段数值，需递增且完成 = 100 |
| `text.csv` | `key, text` | 全部反馈文案，占位符 `{spirit}` `{hint}` `{step}` `{total}` |

## 6. 验证方法

本工程测试（`node tests/config.test.cjs`，实际运行 **115 条断言全部通过**）：

- 导出一致性：`config.generated.js` 与 `render(loadConfig())` 逐字一致。
- 配置完整性：三张表 ID 唯一、字段非空；传闻引用的共鸣存在、默认传闻存在；共鸣与传闻一一对应、精灵名不重复；挑战 `step` 为 1..N 连续、`displayOrder` 不重复且展示顺序 ≠ 正确顺序；文案 key 齐全。
- 数值范围：圆环与进度条各阶段 0–100 且递增，挑战未完成时进度不会达到 100。
- 判定函数：3 × 3 结伴组合穷举（只有对角线成功，失败提示对应传闻）；挑战按正确顺序完成、中途按错清空、首步按错失败；进度值按状态计算。

拆分一致性：用 headless Chromium 对原单文件与拆分版执行同一组 13 步操作（错误共鸣、正确共鸣、挑战按错、按序完成、切换传闻、再次结伴并推进一步），每一步比较页面文本、按钮可用/选中状态、反馈样式、进度宽度与圆环角度，结果完全一致。

作品原有验证：飞书原型合集页说明这组原型“可离线运行”“用于验证主操作链、界面信息和规则反馈”，“全部页面使用原生 HTML、CSS 和 JavaScript，无需安装依赖”。除此之外没有可证实的用户测试记录，本文不作补充。

## 7. 已知限制

- 只有 3 条传闻、3 种共鸣、1 条固定挑战序列；所有精灵共用同一套挑战。
- 图鉴收录与公共巡游路线只以文案/提示呈现，没有实际的图鉴或路线界面。
- 挑战说明文字直接写出了正确顺序（“按观察、稳定、同步的顺序”），难度很低，原型侧重验证流程与反馈而非挑战本身。
- `style.css` 为四个原型共用的样式表原样拆出，包含其它原型的主题变量，本页只用到 `yinyuan` 主题。
