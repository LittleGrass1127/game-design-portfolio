# 中国式考研：最后十二周 · 逆推策划文档

> 本文档根据 `demos/kaoyan.html` 单文件 Demo 的代码与配置逆推整理，数值全部从代码/配置表读出。
> 作品原本是“C# 规则核心 + Unity 界面工程”，另做了一版独立 HTML 保证没有 Unity 也能试玩；本工程整理的是 HTML 版。原 Unity 工程不在本仓库。

## 1. 定位与设计问题

- **类型**：单人回合制生活模拟 / 时间与资源管理，单局约 10–15 分钟，鼠标操作。
- **设计问题**：备考题材里最常见的做法是“点学习就涨分”，玩家很快会发现最优解就是一直学。本作想回答的是——**玩家怎样看懂自己的取舍？**
  - 学习收益受精力和压力影响，休息不是浪费，而是给后面的学习“充效率”；
  - 总分决定总量，单科线决定结构，不能只堆优势科；
  - 预算让“冲刺”和“兼职”抢同一份时间；
  - 预览按真实规则执行一遍，玩家在确认前就能看到确切结果（“预览即结算”），失败可以追溯到具体哪一周、哪一份资源。

## 2. 核心循环

```
查看成绩与状态 → 按顺序排三个时段 → 预览真实收益 → 确认执行
   → （偶数周）处理生活事件 → 查看周报与目标差距 → 下一周
十二周后：结算四科成绩、总分，判定是否录取，给出复盘
```

开局选择：3 种起点（四科初始分不同，但初始总分都是 170）× 3 个目标院校（总分线 320 / 365 / 400）。

## 3. 规则与系统

### 3.1 时间：周 × 时段
- 共 `weeks = 12` 周，每周 `slots = 3` 个时段，一局 36 个时段。
- 同一行动可以重复安排；时段**顺序有意义**——每个时段按“行动开始前”的状态计算效率，再改变状态。
- 计划未排满时，预览用 `previewFiller = rest`（好好睡一觉）补齐空位做参考，确认按钮要求排满。

### 3.2 资源：精力 / 压力 / 生活费
| 资源 | 初始 | 范围 | 作用 |
|---|---|---|---|
| 精力 | 75 | 0–100（clamp） | 低于 60 时学习效率下降 |
| 压力 | 20 | 0–100（clamp） | 高于 35 时学习效率下降；>70 界面标红 |
| 生活费 | ¥950 | 整数，可为负 | 冲刺要花钱；钱不够时不能安排冲刺/付费事件选项；每周固定扣生活费，可欠款，欠款不追加隐藏惩罚 |

每周三个时段结算完后统一进行“周末”：生活费 −60、精力 +12、压力 −5。

### 3.3 行动（11 种，`actions.csv`）
| 分类 | 行动 | 基础收益 | 精力 | 压力 | 花费 | 收入 |
|---|---|---|---|---|---|---|
| 日常自习 study | 政治 / 英语 | +7 | −14 | +9 | 0 | 0 |
| 日常自习 study | 数学 / 专业 | +10 | −14 | +9 | 0 | 0 |
| 冲刺训练 sprint | 政治 / 英语 | +10.15 | −24 | +15 | 25 | 0 |
| 冲刺训练 sprint | 数学 / 专业 | +14.5 | −24 | +15 | 25 | 0 |
| 生活与恢复 life | 好好睡一觉 | — | +34 | −18 | 0 | 0 |
| 生活与恢复 life | 操场散步 | — | +18 | −30 | 0 | 0 |
| 生活与恢复 life | 接一单兼职 | — | −10 | +5 | 0 | +200 |

冲刺收益 = 自习收益 × 1.45，但精力消耗 ×1.7、压力 ×1.67，还要花钱：它是“用资源换时间”的选项。兼职收入在同一周内立即到账，可以支付同周后面时段的冲刺。

### 3.4 生活事件（8 个事件池，`events.csv` + `event-options.csv`）
- 第 2、4、6、8、10、12 周结算后各触发一个二选一事件，一局 6 个，不重复。
- 顺序由种子决定：`makeOrder(事件数, seed)`，LCG（a=1664525, c=1013904223）驱动的 Fisher–Yates 洗牌；默认种子 2027，每开一局种子 +1。
- 效果全部直接写在选项上（预算/精力/压力/四科加分），没有隐藏随机；钱不够的付费选项不可选。
- 事件池的设计：每个事件都是“照顾自己 vs. 多学一点 / 花钱 vs. 省钱”的对照，例如“坏掉的台灯”：花 ¥100 换精力 +12、压力 −10，或省钱换压力 +6、专业 +1。

### 3.5 结局判定
十二周（含第 12 周事件）结束后 `finished = true`。录取条件：

```
总分 ≥ 目标总分  且  每科成绩 ≥ 该科单科线
```

两个条件缺一不可；没有考场随机——“积累的成绩就是最后的考试成绩”。结局页给出差距最大的科目、休息/兼职次数与剩余预算的复盘。

### 3.6 存档
自动保存到 localStorage（新局、确认计划、处理事件后），未确认的计划不保存；可导出/导入 JSON。读档时 `validateState` 做完整校验：字段范围、`finished` 与周数一致、事件顺序必须等于该种子重新洗牌的结果、挂起事件必须落在偶数周、日记逐条校验快照。

## 4. 数值公式（从 `rules.js` 读出）

全部运算用 `Math.fround` 模拟 C# `float`，取整前先按 C# `Single → Decimal` 的 7 位有效数字处理，以保证与原 C# 核心结果一致。

```
精力系数  = min(1, 0.55 + 0.0075 × 精力)          // 精力 ≥ 60 时为 1
压力系数  = 1 − max(0, 压力 − 35) × 0.005          // 压力 ≤ 35 时为 1，压力 100 时为 0.675
学习效率  = 精力系数 × 压力系数                    // 区间 [0.371, 1]
实际涨分  = round1(基础收益 × 学习效率)，成绩 clamp 到 [0, 科目满分]，记录的涨分 = 封顶后的实际差值
```

单个时段的结算顺序：检查预算 → 按**当前**状态算效率与涨分 → 预算 += 收入 − 花费 → 精力、压力各自加变化量并 clamp 到 [0, 100]。三个时段后执行周末结算。

几个由公式推出的数值关系：
- 初始预算 950 − 12 周 × 60 生活费 = 230，不做兼职最多支撑约 9 次冲刺；
- 开局精力 75、压力 20：连续自习两个时段后精力 47、压力 38，第三个时段就进入降效区（效率约 0.89）；
- 一次“睡一觉”(+34/−18) 正好抵消两次自习的压力（2×9），并略多于两次自习的精力消耗（2×14）。

用规则核心实际跑的两条固定策略（起点“稳步起跑”、目标“青川大学”、事件能选第二项就选第二项）：

| 每周安排 | 终局总分 | 终局精力/压力 | 结果 |
|---|---|---|---|
| 三个时段全部自习（科目轮换） | 343.2 | 12 / 100 | 过 320 线 |
| 自习 + 自习 + 睡一觉 | 393 | 100 / 6 | 过 320 线 |

少学一个时段，总分反而高约 50 分——这正是“休息不是浪费”要传达的体验。

## 5. 配置表说明

`config/` 下的表由 `tools/export-config.cjs` 导出为 `src/js/config.generated.js`（`window.GAME_CONFIG`），再由 `rules.js` 的 `buildExamConfig` 组装成原 `exam_config.json` 结构。

| 文件 | 用途 | 字段 | 改了会影响什么 |
|---|---|---|---|
| `exam-config.json` | 基础参数 | `weeks` `slots` `seed` `initialEnergy` `initialStress` `initialMoney` `weeklyExpense` `weeklyEnergy` `weeklyStress` `resourceMax` `eventEveryWeeks` `efficiency{base, energySlope, stressThreshold, stressSlope}` | 局长、开局状态、每周固定消耗与恢复、资源上限、事件频率、学习效率曲线；规则弹窗中的阈值与公式文字也随之变化。`slots` 规则核心要求为 3 |
| `subjects.csv` | 科目 | `index` `key` `name` `cap` | 科目名称、满分（成绩上限、进度条比例、结局满分合计）。`key` 是其他表四科列的列名后缀 |
| `backgrounds.csv` | 开局起点 | `index` `name` `description` `politics` `english` `math` `major` | 四科初始分；分数不能超过满分 |
| `goals.csv` | 目标院校 | `index` `name` `description` `tagline` `total` `min_politics` … `min_major` | 录取总分线与四科单科线，开局卡片标语 |
| `actions.csv` | 行动 | `id` `category` `name` `subject` `gain` `energy` `stress` `cost` `income` `badge` `description` | 行动收益与代价；`category` 决定出现在哪个页签；`subject = -1` 表示不涨分；`badge` 是卡片图标字；`description` 是悬停说明 |
| `events.csv` | 事件 | `index` `symbol` `title` `body` | 事件池与文案；条目数影响洗牌结果（同种子事件顺序会变） |
| `event-options.csv` | 事件选项 | `event` `option` `text` `description` `money` `energy` `stress` `politics` … `major` | 选项效果；`money < 0` 的选项在预算不足时禁用。`description` 是展示给玩家的效果文案，改数值时要同步改文案 |
| `ui-text.json` | 界面文案 | `stressWarn` `previewFiller` `phases[]` `scenes[]` | 压力标红线、未排满时预览补位的行动、每周阶段标题、书桌提示及其触发条件 |

注意：行动和事件选项的 `description` 文案中写了具体数值，改数值时需人工同步（测试不检查文案）。

## 7. 已知限制

- 叙事文案（“十二周”“三十六个时段”“已完成十二周”等）是写死的标题/台词，改 `weeks` 后需要同步改文案。
- 行动、事件选项的效果说明文字含具体数值，与数值列分开维护。
- 规则核心要求 `slots = 3`、科目数 = 4（与原 C# 核心一致），这两项不能只改配置。
- 事件洗牌依赖事件池条目数，增删事件会改变同一种子下的事件顺序，旧存档的事件顺序校验会失败。
- 没有难度自适应或考场随机，结局完全由玩家决策决定（这是设计选择）；对拍用的纯随机策略 90 局（三档目标各 30 局）中有 34 局录取，难度曲线是否合适仍需要真人试玩数据。
- 书桌插画是内联 SVG 模板（不是位图），保留在 `index.html` 的 `<template>` 中，没有抽成单独文件。
