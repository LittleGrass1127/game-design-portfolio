# 团子清洁队 · 逆推策划文档

> 本文从 `demos/tuanzi.html` 的实际代码逆推，并对照飞书策划案《团子清洁队 Demo策划案》核对。文中数值都能在 `config/` 或 `src/js/` 里找到。

## 1. 定位与设计问题

- **类型**：轻量移动收集 + 自动合成 + 局内升级，PC / 移动浏览器，单局 2 分钟。
- **设计问题**：如果玩家只有“移动”一个操作，能不能撑起收集 → 合成 → 交付 → 成长的完整短局循环？
- **答案思路**：把吸附、合成、交付都做成“靠近即触发”的自动规则，玩家只做路线决策：去哪片污渍、什么时候回餐车、要不要多走几步凑合成。
- **体验目标**（飞书策划案）：三秒看懂目标，十秒完成第一次收集，一分钟感到明显成长，两分钟得到完整结算。
- 说明：交付是“回到餐车”后自动触发的，没有交付按键。回车键只用来开始和再来一局。
- 首屏引导：开始卡片用三格说明“移动 → 靠近 → 送回”，底部一行写明目标（两分钟内把 120 只团子全部送回餐车）；局内右下角常驻操作提示。

## 2. 核心循环

```
移动 → 团子进入吸附圈被拉近 → 接触后进背包（跟随队列）
     → 同色同级凑够数量自动合成（可连锁）
     → 回到中央餐车自动交付，换成金币，连送 +1
     → 清理数到达节点 → 四选一升级 → 下一圈更快
     → 120 秒到或 120 个团子清空 → 结算
```

状态机（`main.js`）：`title → play ⇄ upgrade → end → play（重开）`。升级态下 `update` 直接返回，所以移动、吸附、倒计时都会暂停。

| 系统 | 规则（代码实际行为） | 位置 |
|---|---|---|
| 地图 | 世界 1880×1160，逻辑视口 1280×720；6 个污渍区各生成 20 个团子，共 120 个；餐车固定在世界中心 | `game.json`、`patches.csv`、`world.createState` |
| 移动 | WASD / 方向键八方向，斜向归一化；点击或拖动设目标点，距离 ≤18 视为到达；键盘方向键按下会清除指针目标；开局和窗口失焦时清空全部输入（避免上一局的目标点或卡住的按键带进新一局）；活动范围 x∈[45, W−45]、y∈[55, H−45] | `input.js`、`world.movePlayer` |
| 冲刺 | 空格或左下角「冲刺」按钮（触屏可用），持续 0.26 s，速度 ×2.15；基础冷却 4.2 s，“汽水冲刺”改为 2 s；按钮底部有冷却条 | `game.json.dash`、`rules.tryDash`、`rules.dashCooldownRatio` |
| 吸附 | 距离 < 吸附半径（155）时获得拉力 `(420 + (半径 − 距离) × 5) × PullPower`，速度每秒衰减到 2.5%；接触距离 `< 角色半径 24 + 团子尺寸 + 4` 且背包有空位才收取 | `game.json.suction`、`world.updateMotes` |
| 背包 | 基础容量 7；团子按收取顺序跟在身后，间距随等级变大（`dango-levels.followGap`）；满载时 HUD 提示回餐车（只在游玩中显示），团子仍会被拉近但不进包 | `rules.hasRoom` |
| 合成 | 默认 3 只同色同级 → 1 只高一级，新团子落在被合成的最后一只的位置；按“等级从低到高、颜色 0→2”检测，合成一次后从头再查，直到没有可合成组合；最高 7 级不再合成 | `rules.autoMerge` |
| 清理进度 | 每从地面收取 1 只 +1，合成不额外计数；清爽度 = round(清理数 / 120 × 100%) | `rules.collect`、`rules.cleanPercent` |
| 交付 | 角色与餐车中心距离 < 交付半径（122）且背包非空即交付，背包清空，连送 +1，连送计时重置为窗口时长（8 s） | `rules.settle` |
| 连送 | 计时归零后连送清零；HUD 在连送 ≥2 且窗口内显示 | `world.updateCombo` |
| 升级 | 清理数达到 18 / 38 / 60 / 84 / 108 时进入升级态，一局最多 5 次；每次从未获得的升级里抽 4 项；选择后立即生效；键盘 1–4 可直接选 | `rules.beginUpgrade`、`rules.applyUpgrade` |
| 结束 | 倒计时到 0 或清理数达到 120。若背包非空先按正常规则交付；只有提前清空才有时间奖励；结束只执行一次 | `rules.finish` |
| 界面缩放 | 开始 / 升级 / 结算卡片、HUD 和提示按舞台宽度整体缩放：`缩放 = min(1, 舞台宽度 / 1040)`，窄屏、竖屏和小窗口下不再被裁掉；竖屏时舞台下方提示横屏画面更大 | `game.json.hud.uiBaseWidth`、`main.fitUi`、`style.css` |
| 结算档位 | 清爽度 100% →“闪亮”，≥75% →“清爽”，其余 →“加油”；最高分存 `localStorage`，重开时保留；浏览器禁用本地存储时照常结算，只是不记最高分。结算界面按回车或点「再清一条街」重开 | `game.json.endTiers`、`main.endGame` |

## 4. 数值公式

- **团子价值**：`Value(L) = (3^L − 1) / 2` → 1, 4, 13, 40, 121, 364, 1093（L = 1…7）。
  - 三合关系：`Value(L+1) = 3 × Value(L) + 1`，合成后比三只直接交付多 1 点基础价值，所以值得为凑色多走一小段，但错过合成也不会损失大部分收益。
  - 二合打包机下，2 只 1 级（共 2）就能变成 4，所以它同时提高了容量效率和金币效率。
- **交付收入**：
  `本次收入 = Round[ Σ Value(L_i) × (L_i ≥ 2 ? 高等级倍率 : 1) × 交付倍率 × (1 + Min(5, 连送层数) × 0.12) ]`
  其中连送层数取交付**前**的值：第 1 次 ×1.00，第 2 次 ×1.12，第 3 次 ×1.24 …… 第 6 次及以后封顶 ×1.60。
- **合成贴纸**：每次合成立即 +3 金币，连锁合成按实际次数逐次发放。
- **时间奖励**：仅提前清空时 `TimeBonus = Ceil(剩余秒数) × 1`。
- **移动速度**：`speed × (背包为空 ? 空篮倍率 : 1) × (冲刺中 ? 2.15 : 1)`。
- **相机**：每帧 `lerp(当前, 目标, 1 − 0.001^dt)`，并限制在世界边界内；没有屏幕震动。
- **帧步长**：`dt = min(0.033, 实际间隔)`，防止切后台回来后一帧跳太远。

## 5. 配置表说明

`node tools/export-config.cjs` 把 `config/` 打包成 `src/js/config.generated.js`（`window.GAME_CONFIG`），运行时代码只从这里取值。

| 文件 | 导出 key | 条目 | 用途与字段 | 改了会影响什么 |
|---|---|---|---|---|
| `game.json` | `game` | 1 个对象 | 局时长 `durationSec`、世界/视口尺寸、升级阈值 `upgradeThresholds` 与候选数、最高等级、角色初始属性 `player`（速度、吸附半径、容量、合成需求、连送窗口、冲刺冷却、边界等）、冲刺、吸附物理、队列跟随、交付半径、连送步长与上限、时间奖励、HUD 参数（倒计时变红秒数、界面缩放基准宽度）、结算档位文案、最高分存储键 | 单局节奏、成长速度、操作手感。比如把 `capacity` 调大，回餐车的频率会降低；调整 `upgradeThresholds` 会改变升级在一局里出现的时间点 |
| `patches.csv` | `patches` | 6 行 | `id, x, y, r, motes`：污渍区中心、半径、初始团子数 | 地图分布与总团子数（`total` 由此求和），会影响清空难度和时间奖励 |
| `colors.csv` | `colors` | 3 行 | `type, hex, name`：团子颜色。颜色数量也决定了随机生成和合成检测的颜色范围 | 颜色越多越难凑同色，合成频率会下降 |

## 6. 工程结构

| 文件 | 职责 |
|---|---|
| `src/js/config.generated.js` | 配置表导出结果，不手改 |
| `src/js/rules.js` | 纯规则（`window.TuanziRules`）：等级价值、收取、彩虹换色、自动合成、交付公式、连送、升级抽取与效果、冲刺、结算、可复现随机数 |
| `src/js/world.js` | 实体与世界（`window.TuanziWorld`）：初始状态生成、移动与边界、吸附物理、跟随队列、粒子推进、相机、连送计时。无 DOM |
| `src/js/render.js` | Canvas 绘制 |
| `src/js/input.js` | 键盘 / 指针输入 → 方向与目标点 |
| `src/js/audio.js` | WebAudio 短音效 |
| `src/js/main.js` | 状态机、游戏循环、HUD / 弹窗 / 结算界面、粒子浮字等反馈 |

一帧的更新顺序与原单文件一致：计时器 → 移动 → 吸附/收取/合成 → 队列跟随 → 粒子 → 交付 → 相机 → 连送计时 → 升级检测 → 结束检测。

## 8. 已知限制

- 团子只在开局一次性生成，没有中途刷新；清空后就结束。
- 升级抽取：单文件版用 `sort(() => Math.random() − .5)` 打乱再取前 4 个（分布略有偏差），拆分版改成按 `weight` 不放回抽取。权重全为 1 时就是等概率四选一，规则约束（排除已选、每次 4 项）不变。
- 拆分版在 `window.__tuanzi` 暴露了只读的局内状态，方便自动化测试，不影响玩法。
- 视觉常量（道路、餐车、角色造型、粒子数量、音高）仍写在 `render.js` / `main.js` 里，没有抽成配置。
- 升级态和结束检测在同一帧都满足时（例如最后一秒刚好到阈值），会和单文件版一样先弹升级再进入结算。
