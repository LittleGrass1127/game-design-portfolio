# 夜灯街深夜剪辑室 · 逆推策划文档

> 本文由原型代码（`prototypes/yedeng.html` 拆分后的 `src/js/rules.js`）与仓库内作品说明逆推整理，数值均来自 `config/`。

## 1. 定位与设计问题

交互原型，只保留一个核心操作：**按委托选素材 → 排顺序 → 试映看反馈 → 正式放映**。作品说明中的定位是"素材选择、排序与试映"，四个原创交互原型的统一定位是"用于验证主操作链、界面信息和规则反馈"。

要验证的设计问题：

1. **素材分数不是答案**：单看每段素材的稳定度挑高分并不能得到好反馈，顺序（相邻情绪跳跃）和结尾选择同样重要。
2. **反馈只指出问题类型**：试映告诉玩家"结尾没收住"或"中段跳跃大"，但不给标准答案，玩家需要自己调整。
3. **试错零成本**：任何时候都能点卡片或时间轴移除、重排，修改后需要重新试映。

## 2. 核心循环

```
读委托 → 点击素材加入时间轴（最多 5 段）→ 点击时间轴片段移除 / 重新加入以调整顺序
      → 选满 5 段后「开始试映」→ 读反馈（结尾 / 节奏 / 通过）
      → 「正式放映」结算口碑（试映通过与否，放映反馈不同）
      → 「再剪一版」清空重来，或直接点素材 / 时间轴继续改
```

状态：`timeline`（素材 id 数组）、`previewed`（是否已试映）、`finished`（已正式放映）。任何改动都会把后两项重置为 false，所以放映之后不必先清空也能接着改。

首屏引导：时间轴标题下一句话写明目标和操作（`texts.json` 的 `playHint`），反馈条初始文案同样先说目标；素材卡和时间轴片段都显示情绪强度，因为节奏分只看相邻片段的情绪差。

- 「开始试映」：仅当时间轴恰好 5 段时可用。
- 「正式放映」：已试映且未放映时可用。**不要求试映结果为"通过"**，但未通过时放映反馈会说明问题还在（`premiereWarn`），通过时才是好评（`premiereGood`）。
- 放映后「清空时间轴」按钮改名为「再剪一版」。
- 时间轴已满时再点新素材，弹提示"先移除一段"，且不改变试映状态。

## 3. 规则与数值公式

设时间轴已选素材序列为 `c[0..n-1]`，配置见 `scoring.json`。

| 分项 | 公式 | 说明 |
| --- | --- | --- |
| 主题契合 theme | `min(100, 主题素材数 × 18 + (末段标签 == "温暖结尾" ? 28 : 0))` | 标签包含"温暖"或等于"轻松"计为主题素材 |
| 节奏连贯 flow | `max(20, 100 − Σ|c[i].mood − c[i−1].mood| × 15 − |5 − n| × 12)` | 相邻情绪差之和越大越扣分；不足 5 段也扣分 |
| 信号稳定 stable | `Σ stable / n` | 素材稳定度平均值 |
| 总分 total | `theme × 0.42 + flow × 0.38 + stable × 0.2` | 评分环与"口碑"显示 `round(total)` |

试映判定（按顺序，命中即停，`commission.json`）：

1. 末段不是 `portrait`（片尾合影）→ 结尾反馈（warn）
2. `flow < 70` → 节奏反馈（warn）
3. 否则 → 通过反馈（good）

进度条：未试映 `段数 × 11`%；已试映 76%；已放映 100%。

### 数值观察（对全部 7 选 5 排列 2,520 种穷举，本次实际运行）

- 试映结果分布：结尾问题 2,160 种、节奏问题 336 种、通过 24 种。通过方案的总分在 85.88–91.90 之间，节奏分只有 70 和 85 两档。
- 不通过的排列里总分最高 87.70，低于通过方案的最高分 91.90：想拿最高分必须以合影结尾。
- 例：`街角早餐 → 花猫巡街 → 拉面夜话 → 故障笑场 → 片尾合影`，theme 100（5×18+28 封顶）、flow 70、stable 88，总分 86，试映通过。
- 例：`隧道追逐 → 雨夜霓虹 → 故障笑场 → 街角早餐 → 片尾合影`，情绪强度 5→4→3→2→2，相邻差之和 3，flow = 100 − 45 = 55 < 70，判"中段跳跃较大"；theme 82，总分 72。

### 数值调整记录

| 项 | 原值 | 现值 | 原因 |
| --- | --- | --- | --- |
| `scoring.json` `theme.perThemeClip` | 24 | 18 | 原值下 5 段主题素材 = 120 已经封顶，结尾加分 28 被吃掉，不以合影结尾也能拿到最高总分 91.90，分数和试映判定说的不是一回事。改成 18 后，5 段主题素材只有 90，必须加上结尾加分才到 100；不以合影结尾的最高总分降到 87.70。通过方案的分数区间不变。 |

## 4. 配置表说明

| 表 | 用途 | 字段 | 改了会影响 |
| --- | --- | --- | --- |
| `clips.csv` | 素材池，右侧素材卡按此生成 | `id` 唯一键；`name` 名称；`tag` 标签（决定是否计主题、是否算结尾加分）；`mood` 情绪强度 1–5（决定节奏分）；`stable` 稳定度 0–100 | 素材卡数量与文字、三项评分 |
| `commission.json` | 今晚委托 | `title/brief/panelTag/objectives` 委托文案；`timelineSize` 时间轴格数；`requiredEndingClip` 试映要求的结尾素材 id；`previewFlowThreshold` 节奏不达标阈值 | 委托面板、时间轴格数、试映判定 |
| `scoring.json` | 评分系数 | `theme.*` 主题素材判定标签、每段分、结尾加分；`flow.*` 基准、跳跃惩罚、长度惩罚、下限；`weights` 三项权重（和为 1）；`progress` 进度条 | 所有分数与进度显示 |
| `texts.json` | 文案表 | 试映三类反馈、放映结果、toast、进度标签（`{count}` 等占位） | 界面文字 |

## 5. 验证方法

**本工程测试**：`node tests/config.test.cjs`，实际运行 102 条断言全部通过，覆盖：

- `config.generated.js` 与 `config/` 一致（等价 `export-config --check`）；
- 素材表字段齐全、ID 唯一、mood 1–5、stable 0–100；
- 委托引用的结尾素材存在，且其标签与结尾加分标签一致；素材数多于时间轴格数；
- 权重各在 (0,1) 且和为 1；节奏下限低于基准；
- 评分函数定值：空时间轴、上面两条示例方案、单段时的长度惩罚；
- 试映三种判定各一例；时间轴加入 / 已满 / 移除 / 进度标签；
- 结尾要求体现在分数上：穷举 2,520 种排列，通过 24 种，且最高分只出现在通过方案里。

**浏览器对照**：用 headless Chromium 在拆分版和单文件版上执行同一套 24 步点击（选满 → 满时再点 → 试映报结尾 → 换结尾再试映报节奏 → 带着问题放映 → 再剪一版 → 排出通过方案 → 试映 → 放映 → 放映后直接改 → 清空），每一步比较页面文字、按钮可用 / 选中状态、反馈样式、进度宽度和评分环，结果一致，控制台无报错。

**已有验证**：作品说明只写明该原型用于验证主操作链、界面信息和规则反馈，没有试玩数据，此处不补充。

## 6. 已知限制

- **正式放映不要求试映通过**：只要试映过一次就能放映，区别只体现在放映反馈上。原型阶段可以接受，正式版需要决定是否卡结果。
- 排序只能通过"移除再加入"实现，没有拖拽。
- 只有一个委托；`commission.json` 是单对象，多委托需要改成列表。
- `style.css` 保留了四个原型共用的样式（含其他原型的主题段），未裁剪。
